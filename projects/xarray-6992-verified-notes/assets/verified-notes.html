# Verified Repository Notes: `Dataset.set_index` Implementation in xarray

## Verified Call Chain

The `Dataset.set_index` method implementation has been verified through source inspection and testing. The call chain is:

```
Dataset.set_index (dataset.py:3968)
  → Loop over dimension/variable pairs
    → Single variable case: PandasIndex.from_variables (dataset.py:4066)
    → Multi-variable or append case: PandasMultiIndex.from_variables_maybe_expand (dataset.py:4075)
  → Build new_indexes and new_variables dictionaries
  → Call _replace_with_new_dims (dataset.py:4104)
    → calculate_dimensions (variable.py:3104)
    → _replace (dataset.py:968)
```

## Index Creation Pathways

### Single Variable → PandasIndex
- Validates variable is 1D along the target dimension (dataset.py:4062-4065)
- Creates `PandasIndex` from variable values (dataset.py:4066)
- Calls `idx.create_variables()` to generate `IndexVariable` (dataset.py:4067)
- Original variable is removed from dataset (dataset.py:4057)

### Multiple Variables or Append → PandasMultiIndex
- No existing index: Creates new multi-index from all variables (dataset.py:4075)
- With existing index (append): Expands existing multi-index with new levels (dataset.py:4069-4072)
- Uses `pd.Categorical` for consistent level ordering (indexes.py:678)
- Returns both the `PandasMultiIndex` and coordinate variables (indexes.py:656)

## Verified Behavior

| Scenario | Result |
|----------|--------|
| Single variable `set_index(x='a')` | `x` becomes index with values from `a`; `a` removed |
| Multiple variables `set_index(x=['a', 'b'])` | `x` becomes `PandasMultiIndex`; `a`, `b` preserved as level coordinates |
| Append `set_index(x='a', append=True)` | Existing `x` + new `a` form multi-index; `x_level_0` created |
| Invalid variable | Raises `ValueError: "variable(s) do not exist"` |
| Dimension mismatch | Raises `ValueError: "dimension mismatch"` |

# Dataset Replacement Mechanism in xarray - Verified Findings

## Core Replacement Methods

### `_replace` method (`xarray/core/dataset.py`, lines 968-1017)
- **Purpose**: Fastpath constructor for internal use - the main mechanism for creating new Dataset instances
- **Parameters**:
  - `variables`: dict of Variable objects (default: None → copies existing)
  - `coord_names`: set of coordinate names (default: None → copies existing)
  - `dims`: dict of dimension names to sizes (default: None → copies existing)
  - `attrs`: global attributes (default: `_default` → shallow copy)
  - `indexes`: dict of coordinate names to Index objects (default: None → copies existing)
  - `encoding`: encoding attributes (default: `_default` → shallow copy)
  - `inplace`: bool (default: False)
- **Behavior** (verified via runtime tests):
  - **If `inplace=True`**: Directly modifies `self`'s internal state attributes, returns `self`
  - **If `inplace=False`**: Creates new Dataset via `_construct_direct()` with copied state
  - **Critical**: Explicitly passed arguments are used **directly** (not copied). Caller must ensure they are valid and not aliased elsewhere

### `_replace_with_new_dims` method (`xarray/core/dataset.py`, lines 1018-1029)
- **Purpose**: Convenience method for replacing variables while recalculating dimensions
- **Call Chain**: `calculate_dimensions(variables)` → `_replace(variables, coord_names, dims, attrs, indexes, inplace)`
- **Critical Behavior**: Does **NOT** preserve existing variables - the caller must provide ALL variables they want in the result

### `_replace_vars_and_dims` method (`xarray/core/dataset.py`, lines 1032-1047)
- **Purpose**: Deprecated version of `_replace_with_new_dims()`
- **Behavior**: Always recalculates indexes from variables by calling `_replace` with `indexes=None`

## Low-Level Constructor

### `_construct_direct` method (`xarray/core/dataset.py`, lines 941-966)
- **Purpose**: Low-level constructor that bypasses validation
- **Behavior**: Creates new Dataset via `object.__new__(cls)` and directly assigns:
  - `obj._variables`, `obj._coord_names`, `obj._dims`
  - `obj._indexes`, `obj._attrs`, `obj._close`, `obj._encoding`
  - If `dims` is None, calls `calculate_dimensions(variables)`
  - If `indexes` is None, defaults to `{}`

## Dimension Calculation

### `calculate_dimensions` function (`xarray/core/variable.py`, lines 3104-3132)
- **Purpose**: Calculate dimension sizes from a set of variables
- **Returns**: `dict[Hashable, int]` mapping dimension names to sizes
- **Raises ValueError** if:
  - A dimension name conflicts with a scalar variable
  - Dimension sizes conflict between variables

## Dataset Internal State

When `_replace` updates state, these internal attributes are modified:

| Attribute | Type | Description |
|-----------|------|-------------|
| `_variables` | `dict[Hashable, Variable]` | All variables (data + coordinates) |
| `_coord_names` | `set[Hashable]` | Names of coordinate variables |
| `_dims` | `dict[Hashable, int]` | Dimension names to sizes |
| `_indexes` | `dict[Hashable, Index]` | Index objects for coordinates |
| `_attrs` | `dict[Hashable, Any]` | Global dataset attributes |
| `_encoding` | `dict[Hashable, Any]` | Encoding metadata |
| `_close` | `Callable[[], None]` | Function to close file handles |

## Copy Semantics (Verified via Runtime Tests)

- **In-place mode** (`inplace=True`): Returns `self`, same object id, same internal dict ids
- **Non-in-place mode** (`inplace=False`): Returns new object, new internal dict ids
- **Shallow copy**: `attrs` and `encoding` are shallow copied when not passed explicitly (modifying mutable values inside affects both)
- **Direct assignment**: Explicitly passed arguments are used directly (no copying)

## Usage Patterns Observed

**Pattern 1: Simple variable replacement**
```python
new_ds = ds._replace(variables=new_variables_dict)
```

**Pattern 2: Replace with new dimensions**
```python
# Must provide ALL variables (including coordinates)
new_ds = ds._replace_with_new_dims(variables=all_vars_dict)
```

**Pattern 3: In-place modification**
```python
ds._replace(variables=new_variables, inplace=True)  # Returns self
```

**Pattern 4: Indexing operations**
```python
# Pattern used in sel
result = ds.isel(indexers=query_results.dim_indexers, drop=drop)
return result._overwrite_indexes(*query_results.as_tuple()[1:])
# _overwrite_indexes uses _replace internally
```

## Methods Using `_replace` (Verified)

- `isel` - uses `_construct_direct` directly (not `_replace`)
- `sel` - uses `_overwrite_indexes` → `_replace`
- `assign` - uses `update` → `_replace`
- `drop_vars` - uses `_replace_with_new_dims`
- `rename_dims` - uses `_replace`
- `merge` - uses `_replace`
- `update` - uses `_replace` with `inplace=True`

## Methods NOT Using `_replace` (Clarification)

- `load` - modifies data in-place directly, returns `self` (line 707-738)
- `persist` - uses `_persist_inplace` which modifies in-place, returns `self` (line 919-938)
- `assign_coords` - uses `coords.update` → `_update_coords` directly (modifies in-place)

## Edge Cases (Verified)

- **Empty variable dict**: Works, returns dataset with no variables but original dimensions preserved
- **Variables with conflicting dimensions**: `_replace` preserves original dimensions (when `dims=None`), `_replace_with_new_dims` recalculates from variables
- **Partial variable replacement**: Works, only specified variables are replaced
- **Indexes that don't match**: `_replace` accepts any indexes dict, even if it doesn't match coord_names or variables

- Similar pattern to Dataset's `_replace` but for DataArrays

```python
def get_all_coords(self, key: Hashable, errors: ErrorOptions = "raise") -> dict[Hashable, Variable]:
```

## Verified Repository Notes: `assert_no_index_corrupted()` Function

### Function Definition
**Location**: `xarray/core/indexes.py` lines 1407-1425

```python
def assert_no_index_corrupted(
    indexes: Indexes[Index],
    coord_names: set[Hashable],
) -> None:
    """Assert removing coordinates will not corrupt indexes."""
    for index, index_coords in indexes.group_by_index():
        common_names = set(index_coords) & coord_names
        if common_names and len(common_names) != len(index_coords):
            common_names_str = ", ".join(f"{k!r}" for k in common_names)
            index_names_str = ", ".join(f"{k!r}" for k in index_coords)
            raise ValueError(
                f"cannot remove coordinate(s) {common_names_str}, which would corrupt "
                f"the following index built from coordinates {index_names_str}:\n"
                f"{index}"
            )
```

### Corruption Detection Logic
An index is considered corrupted when removing coordinates would **partially overlap** with the index's coordinate dependencies:
- Condition: `common_names and len(common_names) != len(index_coords)`
- Mathematical equivalent: `(I ∩ R) ≠ ∅ AND (I ∩ R) ≠ I` where I=index_coords, R=coord_names

### MultiIndex Coordinate Grouping
**Source**: `xarray/core/indexes.py` line 1165 (`group_by_index()` method)

For `PandasMultiIndex`, the index depends on both the dimension coordinate and all level coordinates:
- Example: MultiIndex with dimension 'x' and levels ['foo', 'bar'] has `index_coords = {'x', 'foo', 'bar'}`
- This grouping is established by `group_by_index()` which returns tuples of `(index, coords_dict)`

