### Execution Flow: `cache['key']`

```
1. Enter __getitem__(self, key)
2. Acquire lock: with self._lock:  ← threading.RLock
3. Retrieve value: value = self._cache[key]  ← O(1) lookup
4. Update priority: self._cache.move_to_end(key)  ← O(1) move to newest position
5. Return value
6. Lock released automatically
```

### Why the Key's Position Changes

The OrderedDict maintains **oldest → newest** order (front to end):
- `move_to_end(key)` marks the key as **recently used**
- Eviction removes from the **front** (oldest)
- This enables O(1) LRU eviction

**Evidence**:
