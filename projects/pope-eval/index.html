Stable rollouts & the decoding recipe that submits

done 2026-08-13

Surveying all 19 ch1.6k rollout dirs, only 3 ever emit the submit sentinel and only 2 are genuinely stable (submit early with no long loop). The lever is decoding config, not the weights: thinking ON is mandatory (no no-thinking run ever submitted), temperature 0.6 (sampling, not greedy 0.0), presence_penalty=0 throughout, and guided decoding required for 4695's full 7-field task8 (optional for the simpler 6992 target). Under this recipe the longest exact-repeat streak drops from 87–170 (collapse) to 2–3 (stable), and the model reaches an actual edit → verify → submit.

Command looping in task8 rollouts (ckpt-300 vs ckpt-600)

blocked 2026-08-13

Two LoRA checkpoints of qwen35_9b_pope_first14easiest_no_task5_lora were merged and evaluated with a free container rollout on pydata__xarray-4695 / task8_full_compositional, identical sampling each time (temp 0.7, pp0, thinking OFF, guided OFF, 200 steps, seed 0). Both fail to submit and both end in the same terminal repetition-collapse — but the later checkpoint reaches it much later.

Checkpoint comparison

CheckpointStepsUnique cmdsSubmittedEarly exploration
ckpt-300200 (cap)77Falseloops almost immediately (wide nl-ba+grep)
ckpt-60064+47False~36 genuine forward steps, correctly reaches convert_label_indexer

ckpt-600 is a clear improvement in early-trajectory navigation (it homes in on the correct 4695 .sel/.loc fix region before collapsing), but succumbs to the same fixed-point attractor once a wide read/grep overflows the 2000-char observation cap — because the eval disables both anti-repetition safeguards used during data generation (thinking + presence_penalty).

Training-data corroboration (raw 4695 bank, 20 seeds)

The bank was generated with thinking ON + presence_penalty 1.5 + temp 0.6. In it, command-looping is exclusively a failed-trajectory phenomenon:

OutcomeSeedsAvg stepsSubmit rateAvg maxIdRunMax maxIdRun
SUCCESS11601.001.32
FAIL9920.4421.2166

Every success pivots READ → RUN → EDIT (sed -i) → TEST (pytest) → SUBMIT with maxIdRun ≤ 2; all heavy looping is in failures. seed_0 collapses onto one read 166× straight to the cap even though that read was not truncated — i.e. repetition-collapse, not truncation-blindness. This isolates the fix to the decoding/harness (restore presence_penalty and/or thinking; add a loop-guard; narrow reads), not checkpoint maturity.

done 2026-08-12

The POPE tasks_v1 training data is 8 supervised SFT variants mined from the xarray minimal-prompt 9B solver trajectories, built on the 14 easiest xarray issues with the ground-truth commit injected. Each task appends a per-step instruction and supervises specific <prediction> fields; task 8 is the full compositional target (all 7 fields) used in the ckpt-300/600 evals above.
