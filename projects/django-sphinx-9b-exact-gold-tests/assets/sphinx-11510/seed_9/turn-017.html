Now I understand the flow:

1. When `.. include::` is processed, docutils reads the file directly using `io.FileInput`
2. If it's not literal, it calls `self.state_machine.insert_input(include_lines, path)` which inserts the included lines into the state machine for parsing
3. The source-read event is never emitted for included files because they're read directly by docutils

To fix this, we need to intercept the reading of included files and emit the `source-read` event. There are a few approaches:

1. Override the Include directive in Sphinx to read the file itself and emit the source-read event
2. Hook into the state machine's insert_input method
3. Use a custom FileInput class that emits the source-read event

Looking at the test cases, the expected behavior is:
- `test_include_source_read_event`: The source-read event should be fired for included files (like `baz/baz.rst`) but NOT for literal includes (like `text.txt`)
- `test_include_source_read_event_nested_includes`: Modifications made in the source-read handler should persist in the final output

Let me think about how to implement this. The key insight is that when an included file is parsed (not as literal), we need to:
1. Read the file content
2. Emit the source-read event with the correct docname
3. Process the content through docutils' parser

But there's a complication - the included content gets inserted into the current document's state machine via `state_machine.insert_input()`. This means the included content becomes part of the parent document's parse tree.

One approach is to:
1. Create a temporary document for the included content
2. Parse the included content into this temporary document
3. Apply transforms to the temporary document
4. Extract the nodes from the temporary document
5. Insert these nodes into the parent document

This way, the source-read event would be emitted for the included content, and any modifications would persist.


I should check if there's already infrastructure in Sphinx for handling this kind of nested document processing.
