Now I have a clearer picture. The docutils Include directive:
1. Reads the file using `io.FileInput`
2. Applies line clipping (start-line, end-line)
3. Applies text matching (start-after, end-before)
4. Converts the rawtext to include_lines using `statemachine.string2lines()`
5. If literal, creates a literal_block node and returns it
6. If code, creates a CodeBlock node and returns it
7. Otherwise, adds the lines to the state machine's input buffer via `state_machine.insert_input()`

To fix this, I need to override the Include directive in Sphinx to:
1. Read the file content ourselves before calling super().run()
2. Emit the source-read event with the included file's docname
3. Apply any modifications from handlers
4. Continue with the normal flow but use the modified content

The tricky part is step 4 - we need to ensure that when docutils reads the file, it gets the modified content. One way to do this is to replace the FileInput object or modify its internal state.

Actually, looking at the code more carefully, I see that after reading the content, docutils doesn't read from the FileInput again. It just processes the already-read content. So if we can modify the content after reading but before processing, we should be fine.

Let me think about this differently. Instead of trying to intercept the file reading, I can:
1. Override the Include directive to read the file first
2. Emit the source-read event
3. Modify the content based on handler results
4. Manually process the content (line clipping, text matching, etc.)
5. Insert the processed lines into the state machine manually

But this is complex because we need to replicate all the logic from docutils' Include directive.

A simpler approach might be to:
1. Override the Include directive to read the file first


2. Emit the source-read event
3. Use a custom FileInput class that returns the modified content when read
4. Call super().run() which will use our custom FileInput

I could create a FileInput subclass that wraps the original content and applies transformations based on what the source-read handlers return.
