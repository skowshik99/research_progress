I see. The `relfn2path` method uses `self.docname` to determine the base directory for resolving relative paths. When processing a nested include, `self.docname` is still `index`, not `baz/baz`.

This is the core issue. The Sphinx Include directive assumes that all includes are resolved relative to the main document's directory, not the included document's directory. But docutils' Include directive resolves includes relative to the current document being parsed.

To fix this, I need to:
1. Track which document we're currently processing
2. Use that document's directory as the base for resolving nested includes

But wait, there's another approach. Instead of using `relfn2path()` for the nested includes, I should use docutils' path resolution logic directly. Let me check how docutils does it.

current_source = self.state.document.current_source

It uses `self.state.document.current_source` to determine the base path. This is set by docutils when parsing documents.
