The fix should be to also alter the collation of FK columns when the referenced PK's collation changes. Let me look at where we need to add this logic.

Looking at the code flow:
1. When `drop_foreign_keys` is True, we drop all FK constraints pointing to us
2. We alter our column with the new type/collation
3. We recreate the FK constraints

The problem is that in step 3, when we recreate the FK constraints, we're not passing the new collation to the FK column.

Actually, looking more carefully, I think the issue is different. When `drop_foreign_keys` is True, the FK columns are altered before being recreated. The alteration uses `_alter_column_type_sql`, which only handles type changes.

Let me check if there's any handling for collation changes in the FK columns.
