Let me understand the issue:

1. When using `db_collation` with a primary key, foreign keys that reference that primary key need to have the same collation.
2. Currently, when migrations are generated for changing a field with `db_collation`, the FK columns don't get the collation specified in their ALTER TABLE statements.
3. This causes MySQL to fail when trying to add foreign key constraints because the collations don't match.

The fix needs to ensure that when an AlterField operation changes the `db_collation` of a primary key, any foreign keys pointing to it also get updated with the new collation.
