I see that ForeignKey passes kwargs to super().__init__(). The db_collation parameter would be passed through. But the issue is that when we're altering an existing FK column, the FK field doesn't have its own db_collation attribute - it only inherits it from db_parameters().

Let me think about this differently. The problem is:
1. When creating a new FK column, the ForeignKey.db_parameters() method now returns the collation from the target field. This should work for CreateModel and AddField operations.
2. When altering an existing FK column (because the referenced PK's collation changed), the AlterField operation needs to also update the FK column's collation.

For case 2, I need to find all FK fields that reference the altered field and update their db_collation attribute.
