For MySQL specifically, the inline FK constraint approach adds the constraint directly to the column SQL. However, when FKs are deferred separately via `_create_fk_sql`, the column alteration happens independently, leaving the FK column without the necessary collation update. The solution requires ensuring the FK column receives the same collation modification as the referenced column before reapplying the foreign key constraint.
