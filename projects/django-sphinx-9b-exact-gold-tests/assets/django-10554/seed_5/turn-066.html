I see. The `as_sql` method generates the SELECT clause from `self.select + extra_select`. For UNION queries, the ORDER BY is applied after the UNION, not before.

The issue is that when you have a UNION query with `.values_list('order', flat=True)`, the SELECT list only contains 'order'. But when you try to order by '-pk', Django fails because 'pk' is not in the SELECT list.

The fix should be to allow ordering by columns that are not in the SELECT list for UNION queries. Instead of raising an error, we should just add the ORDER BY clause as-is.

But wait, for SQLite, which doesn't support ordering by non-selected columns in UNION queries, this would still fail at the database level.

Let me think about this more carefully. The test expects:
```python
(union_qs.values_list('order', flat=True).order_by('-pk'), [-1, 6, 5, 7]),
```

This expects ordering by '-pk' even though 'pk' is not in the SELECT list (only 'order' is selected).

For databases that support this (like PostgreSQL and MySQL), the SQL would be:
```sql
SELECT order FROM reservedname WHERE ...
UNION
SELECT order FROM reservedname WHERE ...
ORDER BY pk DESC
```

And the database would handle it correctly.

For SQLite, which doesn't support this, the SQL would fail. So either:
1. Skip the test for SQLite, or
2. Make the SQL work for SQLite by including 'pk' in the SELECT list.
