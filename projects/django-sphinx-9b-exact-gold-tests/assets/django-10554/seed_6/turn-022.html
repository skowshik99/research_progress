I see! When the combined query has a `values_select`, it tries to set that on all the subqueries. But the issue is that this happens after checking if `compiler.query.values_select` exists. The check is:

```python
if not compiler.query.values_select and self.query.values_select:
    compiler.query = compiler.query.clone()
    compiler.query.set_values(...)
```

This means it only clones and sets values if the subquery doesn't already have a values_select. But what if one of the subqueries already has a different values_select? Or what if neither has a values_select initially?

Let me trace through the failing case more carefully:

1. `qs1 = ReservedName.objects.filter(order__gte=6)` - select = (id, name, order) or similar default columns
2. `qs2 = ReservedName.objects.filter(order__lte=5)` - select = same as qs1
3. `union_qs = qs1.union(qs2)` - combined_queries = [qs1.query, qs2.query], no values_select yet
4. `union_qs.order_by('-pk')` - order_by = ['-pk']
5. `union_qs.values_list('order', flat=True)` - values_select = ('order',), select = ?

The problem is in step 5. When you call `.values_list()` on a combined query, it sets `values_select` but doesn't propagate this to the subqueries. Then when ordering by 'pk', the compiler can't find 'pk' in the select list because only 'order' is selected.
