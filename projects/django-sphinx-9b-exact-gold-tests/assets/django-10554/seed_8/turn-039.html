Now I understand the issue better. The `get_extra_select` method adds extra select columns for DISTINCT queries when ordering by columns not in the SELECT list. However, this doesn't apply to combined queries (UNION, etc.).

For combined queries, the issue is that when you have:
1. A UNION query with `.values_list('order')` 
2. And then order by 'pk'

The subqueries only select 'order', but the ORDER BY clause tries to reference 'pk'. This causes an error because SQLite doesn't support ORDER BY on columns that aren't in the SELECT list for compound queries.

The fix should be to ensure that when ordering is applied to a combined query, the ordering columns are also added to the SELECT list of all subqueries. Let me look at how to implement this.

Looking at the code flow:
1. `as_sql()` is called
2. If there's a combinator, `get_combinator_sql()` is called
3. For each subquery, `compiler.as_sql()` is called
4. Then the SQL parts are joined with the combinator keyword

The issue is that the ordering from the main query is not propagated to the subqueries. When you call `.order_by()` on a combined query, it sets `self.query.order_by`, but this ordering is not applied to the individual subqueries.
