1. `(union_qs.order_by('-pk').values_list('order', flat=True), [-1, 6, 5, 7])` - Order first, then select

The second case is where the issue occurs. When you call `values_list('order', flat=True)`, it only selects the 'order' column. Then when you try to order by 'pk', Django should either:
1. Allow ordering by columns not in the select list (if they're available from the underlying tables)
2. Raise an error because 'pk' is not in the select list

Let me look at how this should be handled. The key insight is that when you have a UNION query and you want to order by a column, you need to:
1. Include that column in the SELECT list of all subqueries

Now I understand the issue better. The problem is:

1. When you have a UNION query with `.values_list('order')`, it sets `values_select` to only include 'order'.

The fix should be to ensure that when ordering is applied to a combined query, the ordering columns are also added to the SELECT list of all subqueries.
