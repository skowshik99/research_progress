The core problem is that calling `qs.order_by().values_list('pk', flat=True)` causes the queryset to re-evaluate and break. When ordering is applied to a union queryset before extracting values, the original query gets re-executed incorrectly, leading to unexpected results.

Looking at the actual test cases, they show that ordering should work on union querysets even when using `.values_list()`. The expected behavior is that `union_qs.order_by('-pk').values_list('order', flat=True)` returns results sorted by primary key in descending order, regardless of which column is being selected. This suggests Django needs to handle ordering on union querysets properly, even when the ordered column differs from the selected column.
