Actually, I need to reconsider how this works. In regular queries, you can ORDER BY columns not in the SELECT list. For example:

This works because Django includes the ordered-by columns in the SELECT.

But for UNION queries, the situation is different. Each part of the UNION must have the same SELECT list. If one part has extra columns for ordering, the other parts would need those columns too, which breaks the UNION semantics.
