I see. When `values_list()` is called, it creates a clone and calls `set_values()`. The `set_values()` method clears the select fields and adds only the specified fields. But it doesn't clear the `order_by` field.

So when you have:
1. `union_qs = qs1.union(qs2)` - Combined query with empty select list (all columns selected)
2. `ordered_qs = union_qs.order_by('-pk')` - Adds '-pk' to order_by
3. `values_ordered_qs = ordered_qs.values_list('order', flat=True)` - Sets values_select to ('order',), but keeps '-pk' in order_by

The issue is that when we have a compound query with ordering, and then call `values_list()` on it, the ORDER BY clause still references the original column, but the SELECT list has changed.

The fix should be to ensure that when we have a compound query with ordering, all necessary columns for ordering are included in the SELECT list of each subquery. This could be done by:
1. Adding the missing columns to the SELECT list before generating SQL
2. Or clearing the ORDER BY when calling `values_list()` if the referenced columns are not in the SELECT list
