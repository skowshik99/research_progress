Now I see the issue. The code tries to match ORDER BY columns with SELECT columns by comparing `src == sel_expr`. When you call `.values_list('order', flat=True)` on a union queryset, the SELECT list only contains 'order'. But when you then try to order by 'pk', the code can't find 'pk' in the SELECT list because it's been replaced by 'order'.

The fix should be to handle the case where the ORDER BY column is not directly in the SELECT list but could be derived from the original query. Let me look at how this could be fixed.

Looking at the test cases:
```python
(union_qs.order_by('-pk').values_list('order', flat=True), [-1, 6, 5, 7]),
(union_qs.values_list('order', flat=True).order_by('-pk'), [-1, 6, 5, 7]),
```

In both cases, the expected result is ordered by 'pk' (descending), but the SELECT list only contains 'order'. This means we need to:
1. Either include all necessary columns in the SELECT list for ordering purposes
2. Or map the ORDER BY columns to their numeric positions even if they're not directly in the SELECT list
